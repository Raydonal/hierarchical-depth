# Golden-value provenance

`tests/testthat/fixtures/golden_htheory.csv` was generated by
`data-raw/generate_golden_values.py`, run against the Python `htheory/`
package **as it stood on 2026-09-05** (no git history exists for this repo, so
there is no commit hash to pin — if the Python package changes in a way that
affects any of `meijer.meijerg`, `background.f_N`/`_f_N_scalar`,
`statfactor.B`/`B_tilde`/`B_prime`, or the exact closed forms, regenerate this
file before trusting new R-side test failures/passes against it).

Environment the CSV was generated under:

- `mpmath` 1.4.1
- `numpy` 2.5.2
- `scipy` 1.18.1
- `meijer.DEFAULT_DPS = 20` (the runtime precision actually used by every
  internal call in `background.py`/`statfactor.py` — `_f_N_scalar`/`_B_scalar`
  do not expose `dps` to the caller, so 20 digits is the ceiling this oracle
  can certify, not an arbitrary choice)

## What's in the CSV

Columns: `func, a_json, s, x, beta0, T0, expected_value_str, dps_used, ok`.

- `expected_value_str` is a **full-precision decimal string** (30 significant
  digits requested from `mp.nstr`, though only ~20 are meaningful per the DPS
  note above) — never a rounded double, so the R-side `Rmpfr` comparison isn't
  capped at double precision.
- `ok = False` rows are **documented failure modes**, not generation bugs —
  keep them and assert on them in `testthat` (e.g. every `func=f_N, a_json=[]`
  row is `ok=False` because `f_N` has no density at `N=0` by design; several
  `B_prime` rows near `x=1e-9` fail because the central-difference step
  oversteps below `E=0`, also expected).
- `func in {meijerg_gamma_chain, meijerg_invgamma_chain}` rows exercise
  `meijer.meijerg` directly at the exact parameter shapes `f_N` builds
  internally (**not** the one extra parameter `statfactor.B` appends) — they
  validate the lowest layer independent of any background/statfactor plumbing
  bug. Note the `a_json=[]` rows for these two are not physically meaningful
  (`G^{0,0}_{0,0}` has no interpretation; production code never reaches this
  shape at `N=0`, since `f_N` raises before calling `meijerg` in that case) —
  they're included for completeness of the grid, not as a correctness target.

## Regenerating

```bash
PYTHONPATH=. .venv/bin/python3 htheoryR/data-raw/generate_golden_values.py
```

(or plain `python3` if not using a virtual environment). Re-run and re-commit the CSV any time the trusted
Python implementation's numerics change; do not hand-edit the CSV.
